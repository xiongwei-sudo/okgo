# 设计方案思路（已定决策）

整理自方案讨论里已经钉死的选择。展开设计见 [技术方案.md](./技术方案.md)，上机步骤见 [GPU部署安装说明.md](./GPU部署安装说明.md)。

日期：2026-11-07。范围只限 `video-redact/`，不改上层 Astro 博客。

## 已定

| 决策 | 结论 |
|------|------|
| 运行形态 | **无容器**。单机 Python / venv / conda，不打 Docker |
| 算力 | **一卡一任务**。队列 `concurrency=1`，增强和打码互斥占同一张卡 |
| 加载 | **按需加载**。任务开始再载入勾选的模型，结束卸载；不在开机时把 N1–N4 全部常驻 |
| 顺序 | **先增强、后打码**。避免先打码再把马赛克放大 |
| 打码目标 | 人脸、车牌、敏感文字。文字只保留身份证号和手机号，不把全部字幕打掉 |
| 打码方式 | 高斯为主，可切马赛克或纯色遮罩；框外扩约 10%–15% |
| 跟踪 | 简易 IoU，检测步长之间沿用上一框，减轻闪烁 |
| 网页 | FastAPI 单页：上传、进度、下载。同源，**不加 CORS**。端口 **6006** |
| 上传 | 先把文件完整写到 `jobs/<id>/`，再入队。不共用临时文件名 |
| 部署机 | AutoDL / SeetaCloud，**RTX 5090 D**（约 32GB）。代码和权重在数据盘 `/root/autodl-tmp/video-redact` |
| PyTorch | 优先用镜像里已有的 CUDA 版；只有不可用时再装 cu128 / cu124 |
| 权重入库 | `weights/*.pt`、`weights/*.onnx` 走 **Git LFS**。样片、任务输出、虚拟环境不进 git |
| 音频 | ffmpeg 把原音轨嵌回。不做人声脱敏 |

## 模型清单

| 环节 | 选定 | 现在怎么跑 |
|------|------|------------|
| 人脸 | MediaPipe Face Detection；失败再用 YuNet ONNX | 可用。YuNet 由 `scripts/download_weights.py` 拉取 |
| 车牌 | YOLOv8n 车牌微调（ultralytics `.pt`） | 多源公开地址尝试。失败则蓝/绿牌颜色启发式，并留下 `PLATE_WEIGHTS_PENDING.txt` |
| 文字 | RapidOCR（检测 + 识别）+ 身份证/手机号正则 | pip 安装；首次推理自拉 det/rec |
| N1 超分 | Real-ESRGAN x2 / x4 | 权重【待补】。OpenCV 放大后再缩回原分辨率 |
| N2 低光 | Zero-DCE++ | 【待补】。降为 CLAHE |
| N2 去噪 / 去糊 | NAFNet、NAFNet-Deblur | 【待补】。降为 `fastNlMeans`、反锐化 |
| N3 稳像 | vidstab；没有则 OpenCV | 【待补】。降为光流稳像 |
| N4 视频超分 | BasicVSR++ | 只保留在方案里，没有单独开关 |

增强顺序固定为：稳像 → 低光 → 去噪/去糊 → 超分。发现权重文件但推理还没接上时，日志写「已发现但仍【待补】接入」，画面仍走 OpenCV。

## 分期

打码：

- M1：CLI / 网页能做人脸模糊并下载
- M2：车牌、马赛克、ffmpeg 音轨
- M3：OCR 敏感过滤、简易跟踪
- M4：单卡队列、按需加载、网页增强开关（进行中，内存队列已是 concurrency=1）
- M5：多卡时一卡一个 worker、配置面板（未做）

增强：

- N1–N3：开关和 OpenCV 降级已接上，专用权重未接入
- N4：未做

## 未定 / 未做

- 车牌微调权重仍可能下不到，启发式只是降级，不是最终检测器。
- Real-ESRGAN、NAFNet、Zero-DCE++、vidstab、BasicVSR++ 的正式推理都还没接。
- 二期队列（Redis + RQ/Arq）、批帧、显存 OOM 自动降级、任务目录自动删除，方案里有，代码里还没有。
- 不做：容器、实时摄像头、云端大模型 OCR、跨镜头再识别、音频脱敏、插帧、多任务抢同一张卡。
- 检测不能保证全覆盖，交付前仍要人工抽帧。
