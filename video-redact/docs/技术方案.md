## 1. 目标与范围

做一个可在浏览器使用的视频脱敏工具：用户上传视频，勾选要打码的类型，服务端逐帧检测并模糊，处理完后下载结果。一期默认覆盖三类隐私目标，与公安视综／业务演示素材脱敏场景对齐。

| 目标 | 表现 | 一期策略 |
|------|------|----------|
| 人脸 | 正面／侧脸可见脸部 | 检测框 + 膨胀后高斯／马赛克 |
| 车牌 | 号牌区域（含中国蓝牌等） | 车牌检测模型；弱则降级启发式 |
| 敏感文字 | 身份证号、手机号等 | 文字框检测 + 规则过滤（正则） |

**明确不做（一期）**：实时摄像头流、云端大模型 OCR、精确字符级擦除、跨镜头人物再识别、音频脱敏。

## 2. 总体架构

```
网页前端（上传 / 选项 / 进度 / 下载）
    │ multipart 上传
    ▼
FastAPI（任务队列 + 文件存取）
    │ 异步任务          ▲ 进度 + 下载 URL
    ▼
打码／增强流水线（解码→检测→跟踪→模糊→编码）
    │ 按帧调用
    ▼
检测器（人脸 / 车牌 / 文字） → 结果视频（可选 ffmpeg 回嵌音频）
```

| 项 | 约定 |
|----|------|
| 运行形态 | 单机网页服务（本机或内网）；模型与视频不出网 |
| 后端 | Python + FastAPI + OpenCV + ffmpeg |
| 前端 | 单页 HTML/JS；中文界面 |
| 计算 | 有 GPU：单卡 + 任务级串行；CPU 可回退 |
| 部署 | **无容器**；单机 Python／venv／conda |

工程目录约定见 [GPU 部署安装说明](./GPU部署安装说明.md)（云机典型路径：`/root/autodl-tmp/video-redact`）。

## 3. 处理流水线

1. **接入与校验** — 接收 mp4／mov／avi；校验大小与时长上限；落盘临时目录；返回 `job_id`。
2. **解码** — OpenCV 逐帧读取；记录 fps、分辨率、总帧数；可选抽帧（全帧或每 N 帧检测）。
3. **多目标检测** — 按用户勾选跑人脸、车牌、文字检测器，输出归一化 bbox + 类别 + 置信度。
4. **框后处理** — NMS、同类合并、外扩 margin；文字类用正则保留身份证／手机号等敏感模式。
5. **时序跟踪** — 简易 IoU 关联（可升 ByteTrack 轻量版），补漏检帧，减轻闪烁。
6. **打码渲染** — 对合并区域做高斯模糊或像素马赛克；可配置强度与模式。
7. **编码与音频** — VideoWriter 写无声轨；ffmpeg 从原片拷贝音轨；清理临时文件。

默认建议：**先增强、后打码**（避免放大马赛克块）。可用 `--enhance` 或网页增强开关编排。

## 4. 检测方案选型

| 模块 | 推荐（一期） | 备选 | 说明 |
|------|--------------|------|------|
| 人脸 | MediaPipe Face Detection 或 YuNet | OpenCV DNN ResNet-SSD | CPU 友好；侧脸／小人脸需调 conf |
| 车牌 | YOLOv8n 车牌微调权重 | OpenCV 颜色+轮廓启发式 | 优先开源中国车牌权重；无权重时降级 |
| 文字区域 | RapidOCR／EasyOCR 检测头 | PaddleOCR det | 一期用检测框即可；识别仅用于敏感过滤 |
| 敏感过滤 | 正则：18 位身份证、11 位手机号等 | 关键词表 | 避免把所有字幕／招牌一律打码 |

**优点**：依赖可装；模块可开关；检测器统一接口便于替换。  
**代价**：长视频 CPU 慢；遮挡／逆光／极小目标可能漏检；文字仅正则时可能过杀或漏杀。

代码落点：`pipeline/detectors.py`；权重由 `scripts/download_weights.py` 拉取。

## 5. 打码与跟踪

| 模式 | 说明 | 默认 |
|------|------|------|
| 高斯模糊 | 适合人脸肤色过渡；核大小随框尺寸自适应 | 是 |
| 像素马赛克 | 块状不可逆感更强，适合车牌／证件号 | 可切换 |
| 纯色遮罩 | 演示用；信息完全不可见 | 可选 |

**跟踪**：相邻帧 IoU ≥ 阈值则继承 `track_id`；短时漏检（如 3～5 帧）用上一框外推或插值，避免马赛克闪烁。外扩 margin 建议框边 **10%～15%**，减少边缘露馅。

代码落点：`pipeline/blur.py`、`pipeline/track.py`。

## 6. 网页与接口

| 接口 | 方法 | 作用 |
|------|------|------|
| `/api/jobs` | POST | 上传视频 + 选项（face／plate／text、模式、强度、增强）→ `job_id` |
| `/api/jobs/{id}` | GET | 状态：queued／running／done／failed；进度百分比 |
| `/api/jobs/{id}/download` | GET | 下载结果 mp4 |
| `/` | GET | 中文单页：上传区、勾选、强度滑条、进度条、下载按钮 |

前端交互：选文件 → 勾选检测类型 → 选模糊／马赛克与强度 → 开始处理 → 轮询进度 → 完成后一键下载。超限给出明确中文错误（文件过大、格式不支持、处理失败）。

代码落点：`web/app.py`；CLI 入口：`cli.py`。云机建议：`uvicorn web.app:app --host 0.0.0.0 --port 6006`。

## 7. GPU 多模型调度

### 7.1 已定路线

- **无容器**；单机单卡（或少卡）。
- **一卡一任务**：视频任务级串行入队；禁止多视频任务抢同一张卡。
- 帧内三模型（人脸／车牌／OCR）默认 **串行** 占用 GPU；批帧拼 batch 提吞吐。
- 打码与跟踪在 CPU。
- 增强与打码共用 Worker 池，互斥占卡。

钉死的本地模型（打码侧）：MediaPipe Face Detection（或 YuNet）；YOLOv8n 车牌微调 `.pt`；RapidOCR（PP-OCRv4 det+rec ONNX）。

### 7.2 进程与队列

| 层级 | 选型 | 约定 |
|------|------|------|
| API | FastAPI | 只接上传／查进度／下载；不直接占 GPU |
| 队列 | 一期内存队列；二期 Redis + RQ／Arq | 每张 GPU 对应 worker **concurrency = 1** |
| Worker | 独立进程 `CUDA_VISIBLE_DEVICES` | 启动时加载启用模型并 warm-up；或按需加载 + LRU |
| 多卡 | 一卡一 worker | 队列按空闲卡投递；不做单任务切卡 |

### 7.3 帧内调度

1. **取帧成批** — 默认 batch=4～8（按显存下调）；可选检测步长 stride=2／3，中间帧靠跟踪补框。
2. **同卡串行推理** — 一批帧上：先人脸 → 再车牌 YOLO → 再 OCR（按勾选跳过）。同一时刻一张卡只跑一个模型 forward。
3. **CPU 后处理** — NMS、正则、跟踪、模糊／马赛克、编码；可与下一批评推理双缓冲重叠。

**不做**：多模型 CUDA 流硬并行抢同一张卡；单帧三模型拆到三卡。

### 7.4 显存与隔离

| 项 | 约定 |
|----|------|
| 常驻显存 | YOLO + RapidOCR 为主；MediaPipe／YuNet 可走 CPU 省显存 |
| 预留 | 约 1～1.5GB 给驱动／碎片；推理前检查 free 显存 |
| OOM | 降 batch → 降检测分辨率 → 改 stride；仍失败则任务 failed 并释放 |
| 框架 | PyTorch YOLO 与 ONNXRuntime OCR 分 session |
| 精度 | 默认 FP16（GPU）；CPU 回退 FP32 |
| 加载策略 | **按需加载** + LRU；任务结束可卸载；热点模型可常驻 |

### 7.5 背压与可观测

- FIFO + 时长／体积限额；超限拒收。
- 队列深度达上限返回 429／忙。
- 每 job 记录：排队时长、各模型耗时、GPU 利用率抽样、峰值显存。

代码落点：`pipeline/queue.py`、`pipeline/pipeline.py`、`pipeline/config.py`。

## 8. 视频增强细化

与打码共用网页壳与任务队列。默认链路建议：**先增强、后打码**。

### 8.1 能力与模型（N1–N4）

| 能力 | 主力模型 | 参数量级 | 说明 |
|------|----------|----------|------|
| 超分（N1） | Real-ESRGAN x2／x4 | 约 17M | 一期主力；逐帧 + 可选轻量时序平滑 |
| 视频超分（二期／N4） | BasicVSR++ | 约 7～12M | 时序更好，显存与耗时更高 |
| 去噪（N2） | NAFNet／Restormer | 约 26～115M | 按质选档 |
| 去模糊 | NAFNet-Deblur | 同家族 | 运动糊／失焦；可选 |
| 低光（N2） | Zero-DCE++／SCI | &lt;1M | 快；质量向可换 Retinexformer |
| 稳像（N3） | OpenCV／vidstab | 无 DL 大模型 | 几何补偿，省显存 |

**一期不做**：插帧补帧大模型、云端生成式全片修复、音频增强。

**当前实现备注**：专用权重【待补】时，`pipeline/enhance.py` 提供 **OpenCV 降级**（稳像／CLAHE／去噪／锐化／同分辨率增强），保证开关与流水线可跑通。

### 8.2 增强流水线

1. 质量诊断（估分辨率、亮度、噪声、模糊度；推荐开关可被用户覆盖）。
2. 按需加载：只加载本 job 勾选的 1～2 个增强模型；热点 Real-ESRGAN 可常驻 LRU。
3. 执行顺序建议：**稳像 → 低光 → 去噪／去糊 → 超分**（避免先超分再放大噪声）。
4. 批帧推理：tile 切片防 OOM；batch 按约 32G 显存调；输出后 ffmpeg 回嵌音频。
5. 与打码衔接：同队列可编排 composite（enhance 完成后再投递 redact）；**禁止两 job 同卡并行**。

### 8.3 32G 显存与调度

| 项 | 约定 |
|----|------|
| 队列 | enhance 与 redact 分类型入队，共享 GPU Worker 池 |
| 并发 | 每卡 concurrency=1；增强与打码互斥占卡 |
| 常驻预算 | 热点超分约数 GB；总工作集建议 &lt;28GB，留 2GB+ 余量 |
| OOM | 降 tile → 降倍率（4×→2×）→ 降分辨率 |
| 加载效率 | 本地权重、启动预热、LRU、下一任务 CPU 预取 |

接口扩展：`POST /api/jobs` 增加 `task_type=enhance|redact|pipeline` 及增强选项／倍率。

## 9. 非功能与风险（NFR）

| 项 | 一期约定 |
|----|----------|
| 时长／大小 | 建议上限：≤5 分钟或 ≤200MB（可配置） |
| 并发 | 每 GPU worker 并发=1；多卡才多任务并行 |
| 隐私 | 任务目录处理后可配置自动删除；默认不落日志帧图 |
| 可观测 | job 日志：帧进度、每类检出数、耗时 |
| 验收 | 样片含人脸+车牌+证件号字幕；人工抽帧确认覆盖率 |
| 依赖与权重 | 人脸／OCR 可公开拉取；车牌与增强专用权重【待补】时降级可用 |
| 仓库 | 源码在 GitHub `okgo/video-redact/`；大权重走 Git LFS |

> **合规提示**：工具用于合法授权素材的隐私保护与演示脱敏。检测无法保证 100% 覆盖，重要交付仍需人工抽检。

## 10. 分期落地

### 打码主线（M1–M5）

| 里程碑 | 内容 | 状态（截至文档写入） |
|--------|------|----------------------|
| M1 | CLI／网页：上传→人脸模糊→下载；中文页+进度 | 骨架已实现 |
| M2 | 车牌检测 + 马赛克模式 + ffmpeg 音频回嵌 | 已实现（车牌权重【待补】时启发式） |
| M3 | 文字检测与身份证／手机号过滤 + 简易跟踪 | 已实现（RapidOCR） |
| M4 | GPU Worker：常驻／按需加载、批帧、stride、队列背压 | 进行中（内存队列 concurrency=1） |
| M5 | 多卡一卡一 worker + 配置面板 | 未做 |

### 增强支线（N1–N4）

| 里程碑 | 内容 | 状态 |
|--------|------|------|
| N1 | Real-ESRGAN 超分可跑通 + 进度下载 | 专用权重【待补】；OpenCV 降级可用 |
| N2 | 诊断建议 + 低光／去噪 | 同上 |
| N3 | 稳像 + 与打码 pipeline | 同上 |
| N4 | BasicVSR++ 可选与质检报告 | 未做 |

### 推荐实施顺序

1. 云 GPU 按 [GPU 部署安装说明](./GPU部署安装说明.md) 装依赖并拉权重。  
2. `bash scripts/smoke_test.sh` 冒烟。  
3. 合入车牌／增强专用权重后关闭降级路径。  
4. 再推进 M4／M5 与 N4。
